소개

펜션 '나린숨'을 운영하며 예약부터 손님 응대까지 서비스의 처음과 끝을 직접 책임져 왔습니다. 그 과정에서 사용자가 실제로 겪는 불편을 먼저 살피는 습관이 생겼고, 이 문제를 기술로 풀고 싶어 개발자의 길을 선택했습니다.

지금은 OZ코딩스쿨 AI 헬스케어 부트캠프 6기에서 Python과 pandas로 데이터를 분석하고, scikit-learn으로 머신러닝 모델을 만들며, FastAPI와 Docker로 모델을 서비스하는 방법을 배우고 있습니다.

데이콘 해커톤에서 교차검증 점수가 지나치게 좋게 나온 원인이 데이터 누수였다는 것을 찾아내고 GroupKFold로 검증 방식을 다시 설계했던 경험처럼, 결과보다 '그 결과를 믿을 수 있는지'를 먼저 확인하는 개발자가 되겠습니다.

일하는 방식

  1. 데이터부터 본다 샘플, 컬럼, 타입 등 데이터의 실제 생김새를 먼저 확인합니다.
  2. 가설을 세운다 결과를 보기 전에 무엇을 기대하는지 먼저 적어 둡니다.
  3. 검증을 의심한다 검증 방식이 공정한지, 데이터 누수는 없는지 점검합니다.
  4. 기록으로 남긴다 과정과 판단 근거를 문서로 남겨 팀과 공유합니다.
